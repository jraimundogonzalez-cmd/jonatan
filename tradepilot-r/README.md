# TradePilot R

**Every R Matters.**

Software premium de gestión de posiciones para traders discrecionales (Forex, índices, materias primas, acciones, cripto). Agnóstico de estrategia y agnóstico de ratio riesgo/beneficio: todo el producto se basa en R como unidad decimal libre, nunca en ratios fijos.

> TradingView sirve para analizar. TradePilot sirve para gestionar.

Este directorio contiene el **blueprint completo** del producto, diseñado antes de escribir una sola línea de código de la aplicación, siguiendo el orden: Blueprint → UX → Base de datos → Arquitectura → MVP → IA → Escalabilidad.

**I16 — Zero Friction** *(invariante permanente, 19)*: TradePilot debe minimizar permanentemente la fricción del usuario. Toda funcionalidad frecuente debe ejecutarse en el menor número posible de interacciones; si una tarea habitual requiere más de 30s o más de 10-12 acciones, debe justificarse con una auditoría de valor o rediseñarse. Se revisa explícitamente en toda especificación desde SPEC-004 en adelante.

**I17 — Evaluate ≠ Execute** *(invariante permanente, 19)*: TradePilot nunca modifica automáticamente el estado crítico de un usuario únicamente porque una regla lo indique. Rule Engine (y, por extensión, cualquier componente que produzca un veredicto o una recomendación — Optimizer incluido, SPEC-005) produce evaluaciones, nunca ejecuta acciones; toda acción pertenece siempre a otro componente responsable, o al propio usuario de forma explícita.

**I18 — Automation Before Interaction** *(invariante permanente, 19)*: TradePilot siempre intenta capturar, interpretar y completar automáticamente toda la información posible antes de solicitar cualquier dato al usuario. Orden obligatorio: 1) captura automática, 2) inferencia segura, 3) interacción manual únicamente cuando sea imprescindible. Primera aplicación completa en SPEC-008 (Trade Capture Engine).

**TradePilot Labs — Adaptive Management Optimization** *(línea de investigación, fuera del MVP)*: creada tras el hallazgo de SPEC-001 sobre el espacio de búsqueda del Optimizer (≈2,3×10¹¹ combinaciones). Objetivo: encontrar algoritmos capaces de explorar ese espacio de forma eficiente (heurísticas, optimización multiobjetivo, búsqueda bayesiana, algoritmos evolutivos). Mientras no concluya, Quant Engine sigue evaluando una única configuración candidata cada vez (SPEC-001 §3.8).

## Nota sobre este repositorio

Este proyecto convive con la aplicación de fitness/nutrición existente en la raíz del repo. Es un producto independiente, con su propio stack, base de datos y ciclo de vida — la carpeta `tradepilot-r/` no depende de ningún código de la app de fitness ni lo modifica. Cuando el proyecto avance a fase de implementación (post-blueprint), se evaluará si conviene un repositorio dedicado o mantener el monorepo.
